# ADR 0002: Hybrid Retrieval with Reciprocal Rank Fusion (RRF) and Optional Cross-Encoder Reranking

## Status
Accepted

## Context
Standard dense vector retrieval fails on specific clinical keywords (e.g. precise drug codes, exact chemical suffixes, exact brand names), while BM25 / keyword search fails on semantic paraphrasing ("drugs causing severe heart problems" vs "cardiovascular thrombotic events"). 

For an enterprise pharma RAG platform, answers must have high precision on specific clinical sections (e.g. *Boxed Warning*) while understanding broader medical questions.

## Decision
1. **Dense Vector Search**:
   - Cosine distance over `Vector(384)` generated by `sentence-transformers/all-MiniLM-L6-v2`.
   - Score computed as $1 - \text{cosine\_distance}$.

2. **Sparse Full-Text Search**:
   - PostgreSQL native `tsvector` with English stemming generated automatically via stored column `to_tsvector('english', content)` and indexed using GIN.
   - Queries parsed via `websearch_to_tsquery('english', query)` and ranked using `ts_rank_cd`.

3. **Reciprocal Rank Fusion (RRF)**:
   - Rank fusion algorithm:
     $$RRF(d) = \sum_{m \in \{vec, fts\}} \frac{w_m}{k + \text{rank}_m(d)}$$
   - Parameter $k = 60$ prevents top-rank bias from dominating results.
   - Robust to different scoring scale distributions (unlike linear weighted sum which requires score calibration).

4. **Optional Cross-Encoder Reranking**:
   - `cross-encoder/ms-marco-TinyBERT-L-2-v2` re-ranks top candidates when `mode=hybrid_rerank`.
   - Toggleable per request and globally via config (`ENABLE_RERANKER=false` by default to preserve developer machine RAM).

## Consequences
- 4 ablation modes available per query (`vector`, `keyword`, `hybrid`, `hybrid_rerank`), enabling automated quality evaluation and ablation studies in Phase 6.
- Zero external vector DB dependencies; single ACID PostgreSQL container manages relational schemas, vectors, and full-text search.
